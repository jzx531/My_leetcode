这个算法可以拆成两层理解：

1. **枚举最终颜色块的排列顺序。**
2. **固定顺序后，用 DP 决定每个气球属于哪一块。**

最关键的是：**我们枚举的是颜色块的顺序，气球本身的位置不移动，只能重新染色。**

## 一、先理解合法结果是什么

题目要求“颜色相同的气球连续摆放”，意思是：

> 一种颜色一旦结束，后面就不能再次出现。

例如：

```text
00011122    合法：0、1、2 各自连续
11100022    合法：顺序不要求是 0、1、2
00000000    合法：允许只剩一种颜色
00022222    合法：允许缺少某种颜色

00011000    不合法：0 出现了两段
```

因此，任何合法结果最多有三个颜色块，并且各块颜色不同。

三种颜色的排列只有六种：

```text
0 → 1 → 2
0 → 2 → 1
1 → 0 → 2
1 → 2 → 0
2 → 0 → 1
2 → 1 → 0
```

例如，对于顺序：

```text
0 → 1 → 2
```

允许的结果可以表示成：

```text
若干个 0 + 若干个 1 + 若干个 2
```

每一段都可以为空，所以也涵盖：

```text
00000        后两段为空
11122        第一段为空
00022        中间段为空
```

这样，枚举六种顺序，就不会漏掉任何合法方案。

## 二、固定顺序后，还需要解决什么

假设现在只考虑：

```cpp
order = {0, 1, 2};
```

最终颜色必须满足：

```text
000...0111...1222...2
```

但我们不知道：

- 第一个颜色块在哪里结束？
- 第二个颜色块在哪里结束？
- 是否应该让某一块为空？

直接枚举两个分界点，会有 \(O(n^2)\) 种组合，\(n=2\times10^5\) 时无法接受。

DP 就是为了高效地决定这些分界点。

## 三、DP 状态到底是什么意思

先用完整二维形式定义：

\[
dp[i][j]
\]

表示：

> 前 \(i\) 个气球已经处理完，颜色符合当前枚举顺序，且第 \(i\) 个气球被染成 `order[j]` 时，最小总费用。

这里：

- `i` 表示处理了多少个气球。
- `j` 表示当前处于第几个颜色阶段。
- `order[j]` 才是这个阶段对应的实际颜色。

例如，顺序是：

```cpp
order = {2, 0, 1};
```

那么：

| 状态 | 第 \(i\) 个气球的目标颜色 | 前缀允许的结构 |
|---|---|---|
| `dp[i][0]` | `2` | 一段 `2` |
| `dp[i][1]` | `0` | 一段 `2`＋一段 `0` |
| `dp[i][2]` | `1` | 一段 `2`＋一段 `0`＋一段 `1` |

前面的颜色段可以为空，但第 \(i\) 个气球一定属于当前阶段。

所以，**下标 `j` 表示阶段，不一定等于颜色编号。**

## 四、为什么只能从前面的阶段转移

仍以顺序：

```text
0 → 1 → 2
```

为例。

如果当前气球放入第 0 段，即染成 `0`：

```text
前一个气球也只能属于第 0 段。
```

因为如果前面已经出现 `1` 或 `2`，现在再出现 `0`，顺序就倒退了。

因此：

\[
dp[i][0]=dp[i-1][0]+cost(i,0)
\]

如果当前气球放入第 1 段，即染成 `1`，前一个气球可以：

```text
属于第 0 段：当前气球开始进入 1 段
属于第 1 段：当前气球继续留在 1 段
```

因此：

\[
dp[i][1]=\min(dp[i-1][0],dp[i-1][1])+cost(i,1)
\]

如果当前气球放入第 2 段，即染成 `2`，前一个气球可以属于：

```text
第 0 段：跳过中间的 1 段
第 1 段：从 1 段进入 2 段
第 2 段：继续留在 2 段
```

因此：

\[
dp[i][2]=
\min(dp[i-1][0],dp[i-1][1],dp[i-1][2])+cost(i,2)
\]

统一起来就是：

\[
\boxed{
dp[i][j]=\min_{0\le k\le j}dp[i-1][k]+cost(i,j)
}
\]

其中：

\[
cost(i,j)=
\begin{cases}
0,& s_i=order[j]\\
t_i,& s_i\ne order[j]
\end{cases}
\]

这里染成哪种不同颜色，都花同样的 \(t_i\)。

## 五、为什么不需要记录更多历史

你可能会想：

> 只记录当前阶段，会不会丢掉前面颜色块的信息？

不会，因为固定颜色顺序后，后面允许出现什么，只取决于当前阶段。

例如，目前都处于 `1` 段的两个方案：

```text
方案 A：000111，费用 10
方案 B：001111，费用 15
```

无论之前分界点在哪，后面都只能：

```text
继续染成 1
或者进入 2 段
```

它们接下来的可选操作完全相同。

所以，费用为 15 的方案没有必要保留。我们只保留当前阶段费用最小的方案即可。

这就是这个 DP 能压缩大量方案的原因。

## 六、完整推演样例 2

输入：

```text
原颜色：2 1 0 1 0 2
染色费：1 1 4 5 1 4
```

这里只分析颜色顺序：

```text
0 → 1 → 2
```

初始化：

```text
dp = [0, 0, 0]
```

每处理一个气球，就计算一组新的状态：

| 已处理位置 | 原颜色 | 染色费用 | 结束于 0 段 | 结束于 1 段 | 结束于 2 段 |
|---:|---:|---:|---:|---:|---:|
| 0 | — | — | 0 | 0 | 0 |
| 1 | 2 | 1 | 1 | 1 | 0 |
| 2 | 1 | 1 | 2 | 1 | 1 |
| 3 | 0 | 4 | 2 | 5 | 5 |
| 4 | 1 | 5 | 7 | 2 | 7 |
| 5 | 0 | 1 | 7 | 3 | 3 |
| 6 | 2 | 4 | 11 | 7 | 3 |

挑几个关键位置解释。

**处理第一个气球，原颜色为 `2`，染色费用为 1：**

```text
染成 0：费用 1
染成 1：费用 1
保留 2：费用 0
```

所以：

```cpp
dp = {1, 1, 0};
```

这里“直接处于 2 段”合法，因为前面的 0 段和 1 段可以为空。

**处理第三个气球，原颜色为 `0`，染色费用为 4：**

上一轮状态：

```cpp
dp = {2, 1, 1};
```

新的状态：

```cpp
next[0] = 2 + 0 = 2;

next[1] = min(2, 1) + 4 = 5;

next[2] = min(2, 1, 1) + 4 = 5;
```

注意，当前气球虽然本来就是 `0`，但如果要放进第 1 段或第 2 段，就必须染色。

**处理第四个气球，原颜色为 `1`，染色费用为 5：**

上一轮状态：

```cpp
dp = {2, 5, 5};
```

当前选择进入 `1` 段：

```cpp
next[1] = min(2, 5) + 0 = 2;
```

它对应的前缀可以是：

```text
0001
```

前三个气球变成 `000` 花费 2，第四个本来就是 `1`，不花费用。

继续处理后，得到：

```text
000112
```

只修改第 1、2、5 个位置：

```text
2 → 0，花费 1
1 → 0，花费 1
0 → 1，花费 1
```

总费用：

\[
1+1+1=3
\]

最终这一顺序的答案是：

```cpp
min(11, 7, 3) = 3;
```

其他五种顺序同样计算，再取全局最小值。

## 七、初始化为什么三个状态都是 0

```cpp
array<long long, 3> dp = {0, 0, 0};
```

这里是针对“尚未处理任何气球”的初始化约定：

> 空前缀费用为 0，可以从任意颜色阶段开始。

如果初始化成：

```cpp
dp = {0, INF, INF};
```

结合当前转移方式，第一个气球仍可以通过 `dp[0]` 进入后续阶段，但三个状态全设为 0 更直接地表达“允许开头颜色段为空”。

处理第一个气球后，每个状态就都具有“最后一个气球属于对应阶段”的实际含义。

类似地，最后取：

```cpp
min({dp[0], dp[1], dp[2]})
```

是因为最终可以停在任意阶段，不要求三种颜色全部出现。

## 八、代码中的 `best` 是什么

之前的代码使用了这一段：

```cpp
for (int j = 0; j < 3; ++j) {
    best = min(best, dp[j]);

    long long cost =
        (s[i] - '0' == order[j]) ? 0 : t[i];

    next[j] = best + cost;
}
```

`best` 是 `dp` 的前缀最小值：

| 当前 `j` | 更新后的 `best` |
|---:|---|
| 0 | `dp[0]` |
| 1 | `min(dp[0], dp[1])` |
| 2 | `min(dp[0], dp[1], dp[2])` |

因此，这个循环只是把下面三行统一写了出来：

```cpp
next[0] = dp[0] + cost0;
next[1] = min(dp[0], dp[1]) + cost1;
next[2] = min({dp[0], dp[1], dp[2]}) + cost2;
```

只有三个状态时，两种写法效率差别不重要，选择自己更容易理解的即可。

## 九、为什么需要 `next`，不能直接更新 `dp`

因为处理当前气球时，三个新状态都必须读取**上一轮**的状态。

如果从左到右直接修改：

```cpp
dp[0] = ...;
dp[1] = min(dp[0], dp[1]) + ...;
```

计算 `dp[1]` 时，`dp[0]` 已经包含当前气球，发生了新旧状态混用。

例如，顺序为 `0→1→2`：

```text
已处理一个 0，费用为 5：
dp = [0, 5, 5]

下一个气球是 1，染色费也为 5。
```

正确计算：

```cpp
next[1] = min(0, 5) + 0 = 0;
```

因为 `01` 本来就合法，不需要染色。

但如果先覆盖：

```cpp
dp[0] = 0 + 5 = 5;
```

然后再算：

```cpp
dp[1] = min(5, 5) + 0 = 5;
```

就把正确答案算错了。

所以使用：

```cpp
计算 next
dp = next;
```

能清楚地保证新旧状态隔离。

## 十、为什么只用三个 DP 状态

二维转移只依赖：

```text
上一行 dp[i - 1]
```

完全不依赖更早的行，所以无需保存整个 `dp[n][3]`。

代码中：

```cpp
dp    // 上一轮
next  // 当前轮
```

就是滚动数组。

六种顺序，每种处理 \(n\) 个气球，每个气球更新三个状态：

\[
O(6\times n\times3)=O(n)
\]

当 \(n=2\times10^5\) 时，约更新 360 万个状态。

另外，总费用可能达到：

\[
2\times10^5\times10^7=2\times10^{12}
\]

因此，费用、DP 和答案都要使用 `long long`。
